# `wechat-style-extractor` 排版判定分析

分析对象：<https://github.com/sennkuwu/wechat-style-extractor>

## 一句话结论

项目先把公众号正文中的 `<style>` 规则通过 `juice` 内联到元素上，然后对正文内的每个元素读取 `style` 声明，按文本长度加权统计颜色、字号和行高，用段落 `margin-bottom` 的中位数估计段间距，再按 DOM 结构计数标题、引用、卡片、分隔线和图片。最后把这些识别结果交给预览和复制流程。

## 参数分组

| 参数 | 代码中的来源 | 判定方式 | 网页中的对应控件 |
| --- | --- | --- | --- |
| 正文颜色 | `color` | 颜色出现时按元素文本长度加权；过滤过亮颜色 | 正文色 |
| 强调色 | `color`、`border*` | 饱和度至少约 0.28，亮度在 0.18–0.82；按权重取最高 | 强调色 |
| 卡片底色 | `background-color` / `background` | 排除接近白色的背景后按权重取最高 | 卡片底色 |
| 正文字号 | `font-size` | 仅统计 12–22px 且标签为 `p/span/section/div` 的值；按文本长度加权 | 正文字号 |
| 正文行高 | `line-height` | 纯数字直接使用；像素值除以字号；只接受 1.2–2.5 | 行高 |
| 段落间距 | `p` 的 `margin-bottom` | 只采集不超过 80px 的值，最后取中位数 | 段落间距 |
| 字距 | `letter-spacing` | 忽略 `normal/inherit/initial`，取加权最高值；没有时默认 0.3px | 字距 |
| 章节标题 | `h1–h6` 数量 | DOM 计数 | 标题尺寸、标题间距 |
| 引用/重点提示 | `blockquote` 或 `border-left` | DOM 计数 | 引用背景、左边框、内边距 |
| 内容卡片 | `section/div/blockquote` | 同时具备非透明背景和内边距或圆角 | 卡片底色、圆角、内边距 |
| 内容分隔 | `hr`、虚线/点线边框、`border-top` | DOM 计数 | 分隔线开关、颜色 |
| 文章图片 | `img` + 背景图 | `img` 数量加 `background-image:url()` 数量 | 图片圆角、图片间距 |

## 预处理和安全边界

项目只接受 `https://mp.weixin.qq.com` 链接，限制跳转次数、响应大小和读取时间；在复制前会移除脚本、iframe、表单等标签，并只允许一组安全属性和 CSS 属性。远程图片和链接只保留 `http/https` 地址。

这些规则是“保留可复制排版”的安全层，不是视觉参数本身。网页将视觉参数和安全说明分开，避免把安全清洗误认为排版模板。

## 对网页设计的取舍

1. 先提供可解释的手动参数，让用户能看到“改哪个参数会影响什么”。
2. 预设只保存参数，不锁死文章内容；未来分析优秀文章时，可以把分析结果映射为同一套 JSON。
3. 复制结果使用内联样式，适配公众号编辑器；但最终粘贴后仍需在微信编辑器中复核，因为公众号编辑器可能重写部分 CSS。

## 当前预设的状态

网页里的“清爽科技、编辑部海报、温柔杂志、极简留白”是待替换的起始预设，用来演示参数组合，不声称来自用户尚未提供的参考文章。收到文章后，建议为每篇文章记录：

- 文章来源和截图证据；
- 识别到的颜色、字号、行高、间距和组件数量；
- 人工修正项及修正原因；
- 预设名称、适用主题和不适用场景。
